工事かんたん請求（テスト版）

## このリポジトリについて
- このリポジトリはテスト専用です。本番環境・本番リポジトリ・本番URLではありません。
- 作業対象は main ブランチです。
- 本番環境には変更を加えないでください。

## 現在の仕様
- 工事データは端末内に暗号化して保存します。
- 暗号化バックアップの書き出し・読み込みに対応します。
- バックアップはアプリのロック解除パスワードで暗号化し、専用パスワードは設けません。
- 旧形式の暗号化バックアップ（KOUJI-KBACKUP-1）も復元に対応します。
- バックアップ復元後は、暗号化保存データを復号して復元対象データと再照合してから完了表示します。
- 30分間無操作で自動ロックします。
- 請求書・見積書・領収書のPDF作成とファイル保存に対応します。
- PDFの自動プレビューは行いません。
- 領収書は入金済みの工事に対して発行します。
- 工事履歴は自動削除しません。
- Dropbox同期機能はありません。

## アイコン
- PWAアイコンは icon.svg を使用します。
- manifest.webmanifest と service-worker.js に登録しています。
- PNG形式の192×192・512×512アイコンは現時点では含みません。

## テスト時の注意
- 実機テストでは、実データを誤って入金済みにしたり、復元で上書きしたりしないよう、テスト用データ・バックアップを使用してください。
- バックアップのパスワードは忘れないよう安全な場所に保管してください。
- 本番環境への反映は、別途確認・承認を得てから行ってください。


パスワード移行時は、設定情報・暗号化データの保存と旧データ削除を読み戻し確認し、失敗時は変更前の各データを差し戻して再確認します。

ログイン開始時は、一時ログイン鍵の保存が成功してからロック画面を閉じます。保存に失敗した場合はロック画面を表示したままにし、再試行できるようにします。

初回パスワード登録時も、パスワード情報の保存後に読み戻し確認を行い、失敗時は変更前の設定へ差し戻して確認します。

一時ログイン状態の保存では、ログイン時刻の保存に失敗した場合に一時ログイン鍵を消去します。ログアウト・自動ロック時の消去は、ログイン時刻と一時ログイン鍵を独立して処理し、それぞれ削除確認を行います。

暗号化データの通常保存時も、保存前の暗号化データと旧データを保持し、新データの読み戻し確認・旧データ削除確認に失敗した場合は、変更前の状態へ差し戻して再確認します。

工事保存と見積書PDF作成の成否を分離しました。工事データの保存に成功した後でPDF作成に失敗しても、保存済み工事データをメモリ上で取り消さず、履歴からPDFを再作成できる状態を維持します。

工事履歴の入金処理では、処理中の入金ボタンを無効化し、既に入金済みの工事への重複した入金処理を防止します。

見積日・請求発行日・領収書記載工事日の保存後照合に失敗した場合、画面上の値だけでなく変更前の日付を暗号化保存領域にも再保存します。差し戻し保存に失敗した場合は、その旨をエラー表示します。

工事項目の編集時、税抜単価は空欄（未設定）または0以上の数値のみ受け付けます。不正な文字列や負数では保存せず、既存単価を維持します。

工事項目の追加では、カテゴリー欄に入力・選択したカテゴリー名を実際の保存先に使用します。新しいカテゴリー名で項目を追加でき、税抜単価は空欄または0以上の数値に限定します。

追加カテゴリーは管理画面だけでなく新規工事のカタログにもタブ表示されます。既定カテゴリー以外の既存カテゴリーも独立したカテゴリーとして扱い、追加した項目を選択・編集できます。

新規工事のカートでは、数量は1以上の安全な整数、単価は0以上の有限数値のみ受け付けます。不正な値や空欄は計算へ反映せず、入力値を元に戻して再入力を促します。

カテゴリー移行処理は旧標準工事項目ID（d数字）だけを対象とします。ユーザーが追加した工事項目のカテゴリー名は、旧カテゴリー名と同じ文字列であっても自動変更しません。

カタログ項目を連続タップしてカートへ追加する場合も、数量が安全な整数の上限に達した後は増加を停止します。

法人情報の選択状態は、バックアップ復元や工事保存失敗後に存在しない法人IDを保持しないよう整合性を修正しました。

30分無操作ロックは、端末時刻が後戻りした場合にもロック判定が遅延しないよう補強しました。

入金処理は同一工事への重複実行を内部でも防止し、領収書工事日・入金日の実日付検証を追加しました。履歴表示は不完全な顧客データでも画面全体が停止しにくいよう補強し、PDF生成前に書類種別・入金状態・明細値を検証します。

履歴中の欠損エントリーで検索処理が停止しないようにし、PDF明細数量は安全な整数に限定しました。
